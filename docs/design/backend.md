# Backend: native x86-64 code from the IR

Plan and status: `docs/plans/cards/A-09-native-backend.md`. This page is the design that the code in `compiler/src/native/` follows.
The input is the verified (and optionally optimised) IR of `docs/design/ir.md`: 22 operations, 5 terminators, SSA with block parameters.
The first target is **x86-64 Linux, a static ELF64 executable, no libc, no linker**.

## 1. Decisions

- Our own encoder (`native/x86.rs`), ELF writer (`native/elf.rs`) and runtime (`native/rt.rs`). No external crates, no assembler or linker at build time.
- Version 1 generates code the simple way: every IR value has a stack slot (`native/gen.rs`, stage N2). Register allocation comes later (N5).
- **Calling convention**, ours but shaped like System V: integers and pointers in `rdi rsi rdx rcx r8 r9`, floats in `xmm0` to `xmm7`, further arguments on the
  stack (pushed right to left, 8 bytes each), result in `rax` or `xmm0`; callee-saved `rbx rbp r12 to r15`; the stack is 16-byte aligned at a `call`.
  `sret` is an ordinary pointer parameter in the IR, so it needs no rule here.
- **Process start**: `_start` aligns the stack, calls the program's entry function (`main`) and ends with `exit_group(0)`.
- **System calls used**: `write` (1), `mmap` (9), `munmap` (11), `exit_group` (231). Nothing else in version 1.

## 2. Semantics the native code must share with the interpreter

The interpreter (`ir/interp.rs`) is the specification. Every row is a test (card A-09, tests).

| Case | Required behaviour | Native code |
|---|---|---|
| `Div`, `Rem`, `UDiv`, `URem` by zero | stop `division by zero` | compare the divisor with 0 and branch to the stop block (the CPU would raise `SIGFPE`) |
| signed `MIN / -1` and `MIN % -1` | wraps: `MIN` and `0` | compare with -1 and branch around `idiv` (the CPU traps) |
| `Shl`, `Shr`, `UShr` by the type's width or more | stop `shifted by the width or more` | compare the count and branch (x86 masks it silently) |
| `Checked` add, sub, mul | stop on overflow | `add`/`sub`/`imul` then `jo` (signed) or `jc` (unsigned) to the stop block |
| plain `Add`, `Sub`, `Mul` | wrap around at the type's width | the bare instruction at the right operand size |
| `Cmp` on floats with NaN | like Rust: `==` false, `!=` true, ordered comparisons false | `ucomisd` flags with the parity flag checked |
| `IntToFloat` | sign-extend from the source width, then convert | `movsx`, then `cvtsi2sd` |
| `FloatToInt` | saturates like Rust's `as i64` (NaN gives 0), then cuts to the target width | `cvttsd2si` (64-bit); the "indefinite" answer `i64::MIN` is checked: NaN gives 0, a positive overflow gives `i64::MAX`, then cut |
| `Trunc`, `ZExt`, `SExt` | as the names say | `mov`, `movzx`, `movsx`/`movsxd` |
| `Load`, `Store` | little-endian, any alignment | plain `mov` |
| `MemCopy` | non-overlapping copy of n bytes | `rep movsb` (small constant sizes inline later) |
| `Print` | bytes to standard output | appended to a 64 KiB buffer (mapped at start); written out when full, at exit and at a stop; text bigger than the buffer goes straight through; no buffer (mapping failed) means a `write` per call |
| `Stop(msg)` | print `stopped: msg` to standard error, exit status 1 | jump to the shared runtime routine with the message |
| `Alloc`, `Free` | zero-length allocations are fine; a freed block may be reused | the runtime allocator (section 3) |
| leaks | counted at the end of a test build | the allocator counts live blocks (test builds only) |

## 3. Runtime (emitted by the backend)

- `rt_write(ptr, len)`: loops over `write` until everything is written or an error occurs.
- `rt_stop(msg_ptr, msg_len)`: writes `stopped: `, the message and a newline to standard error, then `exit_group(1)`.
- **Allocator**: size classes of 16, 32, 64, ... bytes up to 64 KiB, each with a free list; larger blocks go straight to `mmap`. Every block has a 16-byte header
  holding its class (the IR's `Free` carries no size), so a block is 16-byte aligned. Chunks of 1 MiB are taken from `mmap`. Test builds add a live-block counter
  reported at exit (`leaked N allocation(s)`, like the interpreter).

## 4. Status (N1 to N3)

**N1 is done.** `native/x86.rs` (151 instruction forms, each checked byte for byte against the system assembler: golden bytes in
`native/x86_golden.rs`, regenerated by `python3 compiler/tests/native/gen_golden.py`, and re-checked live when `as` is installed), `native/elf.rs` (static ELF64 with
section headers and symbols, so `readelf`, `objdump` and `gdb` can read it) and `native/rt.rs` (start, write, stop, exit, decimal output, the allocator with its leak
counter). Tests run real executables: hello world, `stop`, allocation reuse and zeroing, a large mapping, 100,000 small blocks across chunks, a leak report (status 3),
decimal output. Reused blocks are cleared on allocation, because the interpreter always hands out zeroed memory. N2 (the code generator) is next.

**N2 and N3 are done.** `native/gen.rs` is the simple code generator (every value in an 8-byte frame slot, zero-extended "canonical" integers, fixed templates per
operation, a swap-safe copy for block parameters, stack arguments with padding for alignment). `pelago build [--no-opt] [--leak-check] [-o out] <path>` writes an
executable and `pelago run --native <path>` builds and runs it. The test suite has a third column: every `output_of` test and the example programs also run natively
(plain and optimised IR) and must print the same and exit cleanly with no leak; `native_agrees_on_the_edge_cases` compares the stop messages and exit statuses of about
fifty programs on the rows of the table above (division, shifts, overflow at every width, NaN, conversions, many arguments, 100,000-deep recursion). Known differences:
float remainder (`%`) is refused by the native build. (`float32` rounding after every operation and saturating `FloatToInt` now agree in both engines.)
The benches run in about a millisecond natively (the interpreter: 20 to 60 ms).

## 5. Windows (PE) target

`pelago build --target=windows -o out.exe <path>` writes a PE32+ console executable (`native/pe.rs`): sections `.text`, `.rdata`, `.data` (with the zeroed space) and
`.idata`; image base `0x1_4000_0000`, no relocations (it does not ask for address randomisation), headers of 0x200 bytes. The only import is **kernel32.dll** with five
functions: `GetStdHandle`, `WriteFile`, `ExitProcess`, `VirtualAlloc`, `VirtualFree`. The machine code is the same as on Linux; only the runtime differs (`rt.rs`):

| What | Linux | Windows |
|---|---|---|
| exit | `exit_group` | `ExitProcess` |
| write | `write` loop | `GetStdHandle` then a `WriteFile` loop |
| memory | `mmap` / `munmap` | `VirtualAlloc` (commit and reserve) / `VirtualFree` (release); a failure is a null result |
| start-up stack | 1 GiB `mmap`, lazily taken | 256 MiB `VirtualAlloc` reserved, the top 512 KiB committed; each guard page hit commits 512 KiB more |
| guard | the lowest 1 MiB of the stack is `PROT_NONE`; `SIGSEGV` and `SIGBUS` run a handler on a `sigaltstack` | a `PAGE_GUARD` page 64 KiB above the lowest committed address; a vectored exception handler that commits the next chunk and moves the guard down, and reports an overflow only when the reservation is used up |

**Stack overflow and bad addresses.** Native code is not memory-checked, so the runtime turns a fault into a stop: a fault inside the guard zone (or the guard page, or `STATUS_STACK_OVERFLOW`) prints `stopped: stack overflow`, any other access violation prints `stopped: invalid memory access`; both flush the output buffer, write to standard error and exit with status 1. The interpreter reports its own, more precise memory errors and has a call depth limit, so the messages differ; that is documented, not tested for equality. A function whose frame is bigger than 4 KiB touches each page of it, top down, before it lowers `rsp` (like `__chkstk`), so a big frame meets the guard instead of stepping over it. If the 256 MiB reservation or its first commit fails, the system stack stays and there is no guard (a fault is then `invalid memory access`).

**Output buffer.** When standard output is a terminal (`ioctl TCGETS`; `GetConsoleMode` on Windows) there is no buffer: each `print` is written at once. Redirected output is buffered as described above.

Calls into kernel32 use Microsoft's convention (`rcx rdx r8 r9`, 32 bytes of shadow space, 16-byte alignment): `win_call` in `rt.rs` aligns the stack by itself with `rbp`, so
the runtime does not depend on the alignment of its caller. Our own functions keep the System V-shaped convention of section 1.

How it is tested: where Windows programs can run, `native_must_agree` and `native_agrees_on_the_edge_cases` also build and run the Windows executable.
Directly on Windows (the `windows` job in `.github/workflows/ci.yml`, on `windows-latest`), and on Linux through Wine when `PELAGO_WINE=1 cargo test` is set (Wine is
slower, so it is opt-in; `apt-get install wine64` is enough). With Wine all 391 tests pass, including the Windows column. The `windows` CI job passes too (run 88): the
compiler's own tests, with real Windows executables built and run on a Windows runner.

## 6. Registers (N5) and first measurements

`native/regs.rs` gives integer, boolean and pointer values a register for their whole life (floats have the SSE registers, see below); every other value stays in its frame slot. Liveness is the usual
backward dataflow over the blocks (a block's parameters are defined at its start, a jump's arguments are used by the jump). Each value gets a **list of live ranges** (half open,
with holes), and two values share a register when none of their ranges meet. An instruction reads its operands at an even position and writes its result just after it, so a result
may take the register of an operand that dies there (`gen.rs` builds results so that is safe, see `bin`). The values are taken heaviest first, weighted by `10^loop depth`, and each
gets the cheapest register: memory costs one load or store per use or definition; a callee-saved register (`rbx r12 to r15`) costs a save and a restore per call of the function and
nothing for a second value in the same register; a caller-saved one (`r10 r11 r8 r9 rsi rdi`) is free when no call-like operation lies in the value's ranges and otherwise **splits the
value around each such operation**: it is stored in a frame slot before the call and loaded after it (`Alloc::across`; the store is made once per block). A register is used when it
is no dearer than memory. Preferences only: the register of a related value (first operand of a two-address operation, the other end of a block-parameter copy), then the argument
register the value travels in.

Everything that moves values at once goes through one **parallel move** (`Gen::moves`): the register arguments of a call (and the function address in `r11`), the entry parameters, the
operands of `memcopy` and `print`, and the arguments of a jump. A copy whose target another copy still reads waits; a cycle (a swap, a rotation of arguments) parks one value on the
stack. A branch whose sides need copies makes the one it falls through to in line and puts the other in a stub after the function, so the hot path has no extra jump. Values nothing
reads, and compares fused into their branch, have no location at all (`Where::Dead`). `--no-regalloc` turns the allocator off; the tests run both ways, and also with only 1, 2 or 4
registers of each kind (`gen::REG_LIMIT`, used by `native_must_agree` and `agree`), which pushes every spill and split path through ordinary programs.

**Memory operations (A-11 W5).** `regs::folds` finds the pointers that never need a register. A `Slot` is a frame offset (`Where::Frame`: `lea` where its address itself is needed, `[rbp+off]` where it is dereferenced), and so is a `ptradd` of a constant to it. A `ptradd` of a constant, of an index, or of an index scaled by 1, 2, 4 or 8 (`mul` or `shl` by a constant) is folded into the memory operand `[base + index*scale + disp]` of the loads, stores and small copies that use it, when those are all its uses; the registers it was made of stay live up to them (`assign` resolves the uses). A `memcopy` of a constant size up to 64 bytes is a run of 8-, 4-, 2- and 1-byte moves through `rax` (8 bytes at a time on purpose: a 16-byte load right after two 8-byte field stores does not forward and stalls, which made `structloop` twice as slow), and no longer counts as a call. A `Slot` is cleared only when the code after it in its block does not write every byte before anything else touches it (`Gen::overwritten_first`); clearing uses 16-byte stores up to 128 bytes and `rep stosb` beyond. The encoder has `[base + index*scale + disp]` operands and `movups`, checked against `as` like the rest.

float, small `MemCopy` uses `rep movsb`, and no value is split between a register and memory (a value too rarely used for a register still pays a load and a store per use).

### Floats in SSE registers (A-11 W11)

Floats go through the same allocator as integers, in a second bank: `xmm2` to `xmm15` (`gen::XMM_REGS`). `xmm0` and `xmm1` stay the templates' scratch registers and `xmm0` carries a
float result and the first float argument. Our convention has no callee-saved SSE register, so the whole bank is caller-saved: a float that lives across a call, an `alloc`, a `free`, a `realloc`
or a `print` is stored in its frame slot before and loaded after, exactly like the caller-saved general registers (a `memcopy` with `rep movsb` leaves them alone). The cost model is
the same: a register is taken when the splits around calls cost no more than the loads and stores of memory.

In `gen.rs` a float is `Where::Xmm(x)` or `Where::Mem(off)` (still the home of a float nothing reads and of the frame-only build). `ldf`, `stf`, `fsrc` and `fdst` hide the
difference. Arithmetic is two-address in the result's register (a commutative operation whose result register is the right operand swaps; `-` and `/` build in `xmm0`). `Neg`
flips the sign with `xorps` against a mask built in `xmm1`; `0.0` is `xorps x, x`; `IntToFloat` clears its destination first to avoid the false dependency on the old value. Float
`<`, `<=`, `>` and `>=` fuse with the branch that ends their block (`ucomis` then `ja` or `jae`, operands swapped for `<` and `<=` so unordered gives false); `==` and `!=` need the
parity flag as well and are not fused. The x87 remainder still reads memory: its operands wait in 16 bytes of frame scratch (`Gen::fscratch`). Arguments, parameters and block
parameters are copied by the same parallel move as integers (`Gen::moves`), a cycle of SSE registers parks one on the stack with `sub rsp, 8; movsd`.

Measured (best of 7, this container): `floatloop` 0.357 s to 0.133 s; C `-O2` is 0.150 s (it keeps the float order, so does not vectorise either), C `-O0` 0.229 s.

### Alignment and jump padding (A-11)

Functions start on 16 bytes and loop heads (the target of a jump back) on 16 bytes when that costs at most 8 bytes of no-ops (`Asm::align`). Every jump, and the compare or checked
`add`/`sub` that fuses with a conditional jump, is kept from crossing or ending on a 32-byte boundary by no-ops placed in front of the pair (`Asm::guard_jump`; the JCC erratum of
Skylake-derived Intel cores, which the 8th-generation laptop of the owner has). Measured on this container, shifting a function by 0 to 31 bytes moves collatz by 0.092 to 0.102 s with
or without the padding, so the erratum does not show here; the padding is there for the cores that have it and costs a few bytes of code.

**Select, conditional stops, `lea` (A-11).** `select` is a `cmov`: when the condition is a comparison made by the instruction just before and read only by selects, the comparison is not turned into a bool and the `cmov`s move on its flags (`Gen::flags`); a select reuses the register of the operand that already sits in the result's register and moves the other one in with the opposite condition. `checked_if` is a checked operation whose overflow jump goes to an out-of-line stub that tests the condition and either stops or jumps back (`Gen::cond_stubs`); for a comparison test the stub makes the comparison again, borrowing `rax` and `rcx` with `push`/`pop`, so no bool is kept. A multiplication by 3, 5 or 9 is `lea d, [a + a*2/4/8]` (one cycle instead of three), with the constant on either side; a checked multiplication by a constant is `imul d, a, imm`.

## 7. AArch64 Linux (card A-10)

`pelago build --arch=aarch64 -o out <path>` writes a static AArch64 ELF (`EM_AARCH64`) with no libc and no linker, the same way as for x86-64. Decision (owner: start now, option 1 of the card): a **second generator over the same IR**, `native/gen_a64.rs`, beside `gen.rs`; the machine-level IR waits for A-11. The pieces: `native/a64.rs` (encoder), `native/rt_a64.rs` (runtime), `native/elf.rs` (`write_a64`), `native/gen_a64.rs`.

**Conventions.** Arguments in `x0` to `x7` and `d0` to `d7`, the result in `x0` or `d0`, further arguments in the caller's outgoing area at `[sp + 8k]` (the callee reads `[x29 + 16 + 8k]`); everything but `x19` to `x28` and `x29` is caller-saved; the stack is 16-byte aligned at every `bl`. A frame is `stp x29, x30, [sp, #-16]!`, `mov x29, sp`, `sub sp, sp, #frame`; slots are addressed from `sp`. A frame bigger than a page touches each page, top down, before it lowers `sp`, so it cannot step over the guard. `x16` and `x17` are the encoder's own scratch registers (large offsets), `x14` and `x15` belong to the out-of-line `CheckedIf` tests.

**Semantics (the table of section 2, on AArch64).**

| Case | AArch64 |
|---|---|
| division by zero | `cbz` on the divisor, to the stop; `sdiv`/`udiv` themselves never trap |
| signed `MIN / -1` | `sdiv` wraps to `MIN` and `msub` gives remainder 0 with no check, as the interpreter does |
| shifts by the width or more | `cmp`, `b.hs` to the stop (the hardware would mask the count) |
| `Checked` 64-bit add and sub | `adds`/`subs`, then `b.vs` (signed), `b.hs` (unsigned add) or `b.lo` (unsigned sub, the borrow) |
| `Checked` 64-bit mul | signed: `mul` and `smulh`, overflow when the high half differs from the sign extension of the low half (`cmp x, y, asr #63`); unsigned: `umulh` not zero |
| `Checked` narrow | the operation in 64 bits, then the result compared with its own `sxt`/`uxt` |
| float compares with NaN | `fcmp` and the conditions `eq`, `ne`, `mi`, `ls`, `gt`, `ge`: unordered sets C and V, which makes all of them false but `ne` |
| `FloatToInt` | `fcvtzs`: saturates and turns NaN into 0 by itself; then cut to the width |
| float `%` | `rt_fmod`, bit by bit (musl's algorithm); `float32` is widened and rounded back, both exact |
| vectors (`v2i64`) | NEON: `dup`, `add`, `sub`, `and`, `orr`, `eor`, `shl`, `ushr`, `addp`, `ins` |

**Runtime.** The same routines and state layout as `rt.rs`, over the generic system call numbers (`write` 64, `exit_group` 94, `mmap` 222, `munmap` 215, `mremap` 216, `mprotect` 226, `madvise` 233, `ioctl` 29, `rt_sigaction` 134, `sigaltstack` 132). The `sigaction` structure is built so that it is right with and without a restorer word. Arguments follow the generator's convention (`rt_print(ptr = x0, len = x1)` and so on, see the `Runtime` struct).

**ELF.** Segments are aligned to 64 KiB (the largest page size AArch64 kernels use), so the file is at least that large before the data; x86-64 keeps 4 KiB.

**Testing.** The encoder against `aarch64-linux-gnu-as` (golden words, regenerated by `python3 compiler/tests/native/gen_golden_a64.py`); every differential test also builds and runs the AArch64 program (plain and optimised IR) and compares output, stop message and status with the interpreter; the runtime has its own tests (start, stop, bad address, stack overflow, buffered output, allocator, large blocks, `fmod` against Rust's `%`). Programs run directly on an ARM Linux machine and under `qemu-aarch64` (`apt install qemu-user binutils-aarch64-linux-gnu`) elsewhere; `PELAGO_SKIP_A64=1` skips them. CI: `check` installs qemu, and the `arm` job runs the suite on a native ARM runner.

**Windows on ARM (stage R4).** `pelago build --arch=aarch64 --target=windows` writes a PE32+ ARM64 console image (machine `0xAA64`) importing `kernel32` only, like the x86-64 one. ARM64 images must be relocatable, so the import section ends with a base relocation table that has one block of padding entries and the image asks for dynamic base; the code is position independent. `rt_a64.rs` calls `WriteFile`, `VirtualAlloc`, `VirtualFree`, `ExitProcess`, `GetConsoleMode`, `VirtualProtect` and `AddVectoredExceptionHandler` through the import table; `x18` (the system's) is never touched and `x19` and up, `d8` to `d15` are callee-saved as in the Microsoft convention. The stack is 256 MiB reserved and committed at once with a `PAGE_GUARD` page 256 KiB above its base: the system builds the exception frame at the stack pointer, so a plain inaccessible zone at the bottom (as on Linux) kills the process instead of reaching the handler. The vectored handler runs on its own 64 KiB stack and reports stack overflow and stray addresses as stops. A large block reserves eight times its length (rounded up to a power of two) of address space with `MEM_RESERVE`, commits the part in use, and grows inside the reservation by committing more pages (see the large-block paragraph below); shrinking and outgrowing it copy. These programs run only on a Windows ARM machine (CI job `windows-arm`).

**macOS (stage R4).** `pelago build --arch=aarch64 --target=macos` writes a position independent Mach-O executable (`macho.rs`): `__PAGEZERO`, `__TEXT`, `__DATA` and `__LINKEDIT` on 16 KiB pages, started by `/usr/lib/dyld` through `LC_MAIN` with an empty chained-fixups table, loading no library (no `libSystem`). A first try with a static `LC_UNIXTHREAD` image was killed by macOS 14 at launch, and `dyld` crashes without the fixups table; both were found by running variants on the `macos-14` runner. Apple Silicon refuses unsigned code, so the writer adds an ad-hoc signature itself: a `SuperBlob` holding a `CodeDirectory` with a SHA-256 hash of every 4096-byte page (its own `sha256`, no dependency). The runtime makes Darwin BSD system calls with `svc #0x80` and the number in `x16`; errors come back as a set carry flag with a positive errno, which the runtime turns into the negative form the Linux code expects. Stack overflow and stray addresses use `sigaltstack` and `sigaction` with a small trampoline (`SIGBUS` and `SIGSEGV`, address at `siginfo + 24`). There is no `mremap`, so a large block is mapped read-write with eight times its length reserved (untouched pages cost nothing) and grows inside that. Raw system calls are not a stable Apple interface; the `macos-14` CI job is the check.

**Large blocks without `mremap` (Windows and macOS).** The header of a large block holds its class and one word with the used length (whole pages) in the high bits and the base-2 logarithm of the reservation in the low six bits. Growing within the reservation only commits pages (Windows `VirtualAlloc` with `MEM_COMMIT`) or changes the word (macOS), and the new tail is zero because nothing beyond the used length is ever touched. A request that shrinks the block, or outgrows the reservation, takes the copy path (a new block with a new reservation), so the zero tail never has to be restored. Freeing releases the whole reservation (`VirtualFree` with `MEM_RELEASE`, or `munmap` of the reserved length). Measured before this change: `list_sum` (a 40 MB list) was 3.75x of C -O2 on macOS against 1.24x on Linux.

**Limits.** A function with more than 1 MiB of code is refused: conditional branches reach 1 MiB. **Registers (stage R3).** `regs_a64.rs` gives the busiest values a home for their whole life: integers, booleans and pointers in `x19` to `x28`, floats in `d8` to `d15` (the low halves of which are callee-saved too, so calls and the runtime leave them alone and no value is ever split or spilled around a call). The analysis is a backward liveness dataflow; each value gets its live range (the runs of positions from a definition to its last read, a jump counting as a one-position write of the parameters it leads to; two values share a register when their ranges are apart, or meet only where a jump hands one to the other or where an operand dies in the instruction that makes the result, for templates that read everything before they write), values are taken heaviest first (uses weighted by `10^loop depth`, at least 3 to pay for the save and restore) and take the first register whose values do not meet theirs. A value whose interval touches no call (function call, `alloc`, `free`, `realloc`, `print`, `memcpy`, float remainder) takes a caller-saved register first, `x0` to `x8` or `d2` to `d7`, which needs no save; a parameter may stay in the register it arrives in. Vectors and everything that does not win a register keep their frame slot. A function saves only the callee-saved registers it uses, in an area above the outgoing arguments. The templates read through `rd` / `wr` (the home, or a scratch register loaded or stored around it), so a register operand costs no move. `Options.regalloc = false` gives the frame-only code; the tests run each program with no registers, all of them and (in `cfg(test)`) two, and require the same result. No measurements on real ARM hardware yet.
